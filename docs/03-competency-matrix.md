# Matriz de competencias

| Competencia | Evidencia mínima | Evidencia sólida |
|---|---|---|
| Componentes | Render y eventos funcionales | Límites claros y API pequeña |
| Signals | Usa `signal` | Deriva con `computed` y evita sincronización duplicada |
| Templates | Usa control flow | Identidad estable, vacío y semántica correcta |
| DI | Inyecta servicios | Controla alcance y usa tokens cuando existe configuración |
| Router | Navega a detalle | URL restaurable, lazy loading y ausencia manejada |
| Forms | Valida campos | Reglas cruzadas, dependencia y payload normalizado |
| HTTP | Camino feliz | Loading, error, vacío, cancelación y feedback |
| RxJS | Usa operadores básicos | Modela tiempo y cancela trabajo obsoleto |
| Arquitectura | Separa archivos | Dependencias coherentes y ownership defendible |
| Testing | Crea componente | Interactúa con DOM, espera estabilidad y cubre riesgo |
| Accesibilidad | Labels y botones | Teclado, foco, nombres, estados y errores comprensibles |
| Depuración | Lee errores | Aísla causa con DevTools, Network y reducción del caso |
